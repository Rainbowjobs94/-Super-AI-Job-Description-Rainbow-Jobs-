# Decision and skip disclosure

When a user chooses, declines or skips a consequential task, explain:

1. Exactly what changes and what is preserved.
2. Features gained, disabled, removed or deferred.
3. Prerequisites, paid costs and resource/runtime requirements.
4. Data/rights/financial consequences.
5. Reversible fallback usable now.
6. Acceptance evidence and the unblock step.

Use plain statuses, not “complete” for stubs or disabled interfaces.
Do not ask the user to choose routine technical implementation details.

| Current boundary | Gain | Disabled/deferred | Usable fallback |
|---|---|---|---|
| Quarantine uploads | Preserved sources and provenance | Immediate source overwrite or execution | Approved CLI merge preview/apply |
| Operator token | Private file/catalog access | Anonymous operator APIs | Static UI remains visible |
| Compact master skill | Lower repeated context cost | Loading every skill in every prompt | Search index, open specific module |
| Zero added AI spend | Local bounded planning | External general AI generation | Structured task candidates and manual agent handoff |
| Deployment candidates | Duplicate address/role detection | Self-certified live deployment | Read-only chain verification in separately approved work |
| Unsigned ltproof | Portable contribution/consent statement | Price, tax, identity, ownership or ZK certification | Reviewed evidence collection and qualified verification |
| CLI-only apply | Explicit overwrites and rollback journals | Autonomous cross-project writes | Download bundle plus source/destination mappings |

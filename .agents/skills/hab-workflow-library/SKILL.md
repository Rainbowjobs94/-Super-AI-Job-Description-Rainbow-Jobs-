# Development, research and governance workflow library

Read `references/domain-playbooks.md`, choose one domain and preserve the user's
original request. Split run-on requests into evidence, tasks and consequential
decisions without silently inventing permissions or economic/legal conclusions.

## Shared contract

Input: bounded goal; opaque project/source identifiers; revisions/hashes;
public or synthetic metadata; required jurisdiction/time window when relevant.
Output: proposed steps; source/evidence matrix; risks; test/acceptance checks;
review roles; missing decisions; rollback; disabled capabilities.

Default: preparation only, no network, zero added provider spend, no public
posting/deployment, no filings, no private-content egress, no key handling,
no signing/minting/trading/custody or self-granted roles. Host permissions must
be enforced separately. A workflow ticket is not an authorization receipt.

The n8n JSON files are in the hab-n8n-control module and its separate workflow
ZIP. This module supplies readable domain plans; it does not require n8n.
Manual packets and reviewed file-based handoffs remain available.

## Evidence rules

- Source timestamps, file hashes and signatures support provenance/integrity;
  they do not by themselves establish IP ownership, patent novelty, freedom
  to operate, enforceability or market value.
- Copyright, trademark and patent are different rights. Jurisdiction, parties,
  dates, licenses/assignments and qualified review matter.
- Legal/compliance preparation is general issue spotting, not legal advice or
  certification. Unknown jurisdiction blocks a definitive legal conclusion.
- A search with no matching patent/trademark result is not clearance.
- Market snapshots require source time, method, units and uncertainty. No
  guaranteed forecasts, autonomous trades or personalized investment advice.
- Missing telemetry/error records is not proof a deployment or fix succeeded.

Use the smallest relevant library skill on the authorized host, including
RepSU/security, evidence-synthesis, deployment-pipeline-design or systematic
debugging where available. Do not flatten all skill bodies into every prompt.

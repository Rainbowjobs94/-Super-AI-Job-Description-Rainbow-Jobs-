# Bounded task planning

Preserve run-on requests. Extract candidates, retain uncertainty and confirm
ambiguities that affect authority, money, privacy or destructive behavior.
Do not infer “deploy” from a keyword or treat a candidate as approval.

Prefer deterministic tools and cheap evidence checks. Set budget, bounded retries
and acceptance tests. Reuse source hashes and idempotency checkpoints. Zero
external-model calls is the default; obtain permission for paid services.
Local planning units are not provider credits. Never promise unlimited capacity
or evade account limits.

Explain gains, disabled/removed/deferred features, cost, privacy consequences,
fallback and unblock steps for consequential choices. Do routine implementation
without forcing the user to pick technologies.

Record IMPLEMENTED only after source exists, TESTED only after the named checks
ran, and live status only after actual deployment evidence. Failed or partial
work must retain a checkpoint and a specific blocker.
